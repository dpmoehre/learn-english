# ✅ 已完成：查清前两句没声的原因

- **现象**：第 3 句 `I'm happy to be here` 有声；`Hi, I'm Lin.`、`I'm new to the team.` 没有。
- **原因**：有道 `dictvoice` 是词典发音，不是整句 TTS。前两句 HTTP 500；第 3 句是常见整句，返回 mp3。
- **误伤**：曾把所有 Apple 设备改成有道优先，iPad 原来能用的系统朗读被盖住。

# 🚧 进行中：系统朗读 + 网络发音切换

- **目标**：三句都能听；iPad 恢复系统朗读；iPhone 静音拨片下也能听。
- **做法**：
  - 默认：iPhone = 网络发音，其他 = 系统朗读
  - 网络：百度翻译 TTS（`referrerpolicy=no-referrer`），失败再试有道
  - 课程里可切换「系统朗读 / 网络发音」
- **验收**：iPad 点第 1、2、3 句都有声；iPhone 刷新后点听有声或能靠切换恢复。
- **证据**：待用户真机回复。

# 🚧 进行中：外企词典听词没声

- **原因（第二层）**：线上从 GitHub Pages 请求百度会返回空页；`FYI` 被拆成 `F Y I` 后再请求有道会 500；失败后再播已经离开这次点击。
- **原因（第三层）**：同一次点击里系统朗读 + 两条网络音在 iPhone 上互抢音频会话，结果全部没声。
- **原因（第四层，根因）**：听词按钮写成 `onclick="speakEnglish("HR")"`，引号把点击事件截断，点下去根本没播放。
- **做法**：按钮改为 `speakFromButton(this)`；录音用本页 `audio/dict/*.m4a`。整句仍走系统朗读。
- **验收**：打开 `?v=20260917g#vocab`，点 `offer`、`HR` 能出声；文案含「版本 20260917g」。

# ✅ 已完成：offer 等词提示录音没准备好

- **原因**：录音文件名是 `Offer.m4a`，页面请求 `offer.m4a`。本机不区分大小写能播；GitHub Pages 区分，iPad 就失败。
- **做法**：文件名和请求都改成小写；缺文件时改用系统朗读，不再只提示「还没准备好」。
